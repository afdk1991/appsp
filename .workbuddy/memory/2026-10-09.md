## GitHub 推送打通（关键突破）
- 用户再一次"已重新授权"后，发现真正可用通路是 **HTTPS + Git Credential Manager(GCM) OAuth**，而非 SSH/连接器：
  - `git remote set-url origin https://github.com/afdk1991/appsp.git`
  - `git push -u origin main`（首次走浏览器 OAuth 授权）
- 本机已装 GCM 2.9.0（`C:/Program Files/WorkBuddy/resources/vendor/PortableGit/mingw64/bin/git-credential-manager.exe`），
  `~/.gitconfig` 的 `credential.helper` 指向它；`git-credential-manager diagnose` 7 项全过（含 Credential storage、GitHub API）。
- **一次性推送 13 个提交 / 75 个文件成功**（`d06f0fd..aef1d1a`），并用 GitHub API 独立核验 `pushed_at` 与提交列表一致。
- 经验：headless 下 `git push` 会因等待 GCM 交互而挂死；用 `GIT_TERMINAL_PROMPT=0` + **输出重定向到文件**（勿用管道）可正常完成；
  若令牌缓存失效则需在后台跑 push，由用户点掉浏览器授权窗口后自动落库。
